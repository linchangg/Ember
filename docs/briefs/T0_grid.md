## Steps

1. Add dependencies, from `engine/`:
   ```bash
   uv add pyproj pyyaml xarray rioxarray rasterio
   ```

2. **`data/scenarios/eaton/scenario.yaml`.** Copy the YAML block from `spec/00_contracts.md` §2 **exactly**, comments included. Don't change any value.
3. **`engine/emberline/data/config.py`:**
   ```python
   REPO = Path(__file__).resolve().parents[3]          # repo root
   def scenario_dir(scn: str) -> Path: return REPO / "data" / "scenarios" / scn
   def load_scenario(scn: str) -> dict:                 # yaml.safe_load of scenario.yaml
   def utc_ms(iso: str) -> int:                         # "2025-01-08T02:15:00Z" -> epoch ms
   ```
   Plain dicts are fine; don't write a Pydantic model for the config.
4. **`engine/emberline/data/grid.py`.** Every function takes `g`, the `grid` dict from `scenario.yaml` (`crs`, `cell_m`, `nx`, `ny`, `x0`, `y0`), so Palisades works with a different config:
   - `transform(g) -> affine.Affine`: `Affine(cell_m, 0, x0, 0, -cell_m, y0)`. `affine` comes with rasterio.
   - `cell_centers(g) -> tuple[np.ndarray, np.ndarray]`: 1-D arrays `xs` (len nx) and `ys` (len ny). `x = x0 + cell_m/2 + cell_m·col`; `y = y0 − cell_m/2 − cell_m·row`.
   - `xy_to_lonlat(x, y, g)` and `lonlat_to_xy(lon, lat, g)`. Use a module-level cached `pyproj.Transformer.from_crs(g["crs"], "EPSG:4326", always_xy=True)` and its inverse. Accept scalars or numpy arrays.
   - `xy_to_rowcol(x, y, g) -> (row, col)`: integer floor; return `-1` for points outside the grid.
   - `corners_lonlat(g) -> dict`: the **outer** corners `{"tl": [lon, lat], "tr": ..., "br": ..., "bl": ...}`, where tl = `(x0, y0)`, tr = `(x0 + nx·cell_m, y0)`, br = `(x0 + nx·cell_m, y0 − ny·cell_m)`, bl = `(x0, y0 − ny·cell_m)`.
   - `bbox_lonlat(g) -> (west, south, east, north)`: min/max over the 4 corners.
   - `template(g) -> xarray.DataArray`: zeros `float32`, shape `(ny, nx)`, dims `("y", "x")`, coords = cell centres, then `.rio.write_crs(g["crs"])` and `.rio.write_transform(transform(g))`. This is what every raster is aligned to with `rio.reproject_match`.
   - `write_grid_json(scn: str) -> Path`: writes `data/scenarios/{scn}/grid.json` = `{"crs", "cell_m", "nx", "ny", "x0", "y0", "transform": [6 affine numbers a, b, c, d, e, f], "corners": corners_lonlat(g), "bbox": bbox_lonlat(g)}`, with `indent=2`.
   - `if __name__ == "__main__":` takes `--scenario` (default `eaton`), calls `write_grid_json` and prints the corners.
5. Run `uv run python -m emberline.data.grid --scenario eaton` and commit the generated `grid.json`.
6. **`engine/tests/test_grid.py`** (all offline). These are the acceptance tests:
   - `01` §12 test 1: for each corner, `lonlat_to_xy(*corner)` returns the original UTM corner within **1 m**.
   - Coverage (`01` §1): the bbox is about lon −118.288..−117.957 and lat 34.061..34.337 (each within 0.01°).
   - The ignition point (−118.088, 34.205) maps to a valid row/col. A point on Lake Ave (−118.1316, 34.20) maps to a valid row/col.
   - Cell centre of row 0, col 0 = `(381525, 3800235)`; row 339, col 339 = `(381480 + 45 + 90·339, 3800280 − 45 − 90·339)`.
   - `template(g)` has shape (340, 340), CRS EPSG:32611, and `.rio.transform()` equal to `transform(g)`.
   - `grid.json` on disk equals a freshly computed one (catches a stale committed file).
7. `uv run pytest -q`. The whole suite passes.
8. Open the PR (README §2 rule 12), and tell Cody it's ready so T1 and T6 can start.
